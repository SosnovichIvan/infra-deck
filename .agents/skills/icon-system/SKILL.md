# Icon system

Продолжи существующую систему иконок или создай минимальный согласованный набор.
Skill независим от UI/UX и frontend skills. Сначала проверь установленную
библиотеку/ассеты; не добавляй второй набор, если требуемый символ уже доступен.

## Контракт набора

Определи значения символов, размеры применения, grid/viewBox, stroke/fill,
толщину, caps/joins, optical bounds, темы и способ интеграции. Выведи правила из
существующих иконок. Новая сетка — решение для нового набора, не универсальные 24px.

У одинаковых действий должны быть одинаковые символы. Для неоднозначного
действия добавь понятный label вместо усложнения рисунка. Directional icons
проверяй для RTL; не зеркаль автоматически логотипы, числа и универсальные символы.

## Геометрия и файлы

- Проектируй векторно через доступный editor или SVG paths. Raster tracing
  требует ручной проверки; bitmap в SVG не делает иконку редактируемым вектором.
- Согласуй визуальный вес, отступы и оптический центр на фактическом размере;
  одинаковый bounding box не гарантирует одинаковое восприятие.
- Сохраняй viewBox, формы и IDs при оптимизации. Проверь отсутствие clipping,
  зависимостей на внешние fonts/images и конфликтов IDs при нескольких экземплярах.
- В одноцветном UI используй принятую модель цвета, например currentColor,
  если она подходит интеграции. Не уничтожай смысловые цвета многокрасочной иконки.
- При импорте недоверенного SVG проверь script, event handlers, foreignObject
  и внешние ссылки; не вставляй raw SVG без принятого sanitization pipeline.
- Сохраняй требования лицензии/атрибуции при использовании библиотечных ассетов.

## Интеграция и проверка

Декоративную иконку скрывай от accessibility tree; смысловой элемент получает
имя на уровне соответствующего контрола. Не дублируй озвучивание через SVG title
и button label. Маленький рисунок может находиться внутри большей области
нажатия — не увеличивай stroke ради hit target.

Отдай SVG и запрошенные wrappers/exports с едиными именами. Создай contact sheet
для набора и проверь целевые размеры, светлую/тёмную тему и несколько экземпляров
на одной странице. Для одной правки достаточно до/после на целевом размере.
В preview задавай размеры фактически вставленного элемента: CSS для svg не
влияет на img с SVG-файлом. Внешний SVG в img не наследует currentColor от
контрола. Для монохромного currentColor-набора в themed preview используй inline
SVG или CSS mask; img подходит с отдельно заданными цветными вариантами.
Проверь, какой элемент фактически задаёт цвет каждой темы; наличие тёмного
фона само по себе не доказывает видимость иконки.
Если по задаче кнопка содержит видимый текст, aria-label не заменяет этот текст.
Без визуального просмотра укажи ограничение, а не заявляй optical QA пройденным.

## Профиль правил проекта

Применяй [профильные правила](references/project-rules.md) только при явном согласии
на правила этого скилла в инструкциях проекта. При наличии approved snapshot
используй его; наличие файла само по себе не активирует правила. Они не запускают другие скиллы автоматически.
