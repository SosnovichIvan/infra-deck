# Требования

Требования описывают целевой продукт; все сценарии пока planned.

| ID | Возможность | Критерий приёмки |
| --- | --- | --- |
| AUTH-01 | Регистрация: логин, пароль, подтверждение | Несовпадение отклоняется; логин уникален; пароль хранится как хеш; confirmation не сохраняется |
| AUTH-02 | Вход по логину и паролю | Рабочие вход/выход; rate limit; неверные данные не раскрывают существование пользователя |
| INV-01 | Реестр VPS и VM | Пользователь видит свои узлы, окружение, местоположение, доступность и последнее наблюдение |
| INV-02 | Реестр сервисов и развёртываний | Видны версия, узлы, endpoint, зависимости, состояние и источник обнаружения |
| AGENT-01 | Установка агента backend-ом | SSH с проверкой host key; подписанный пакет; повтор установки безопасен; результат и ошибка доступны в UI |
| AGENT-02 | Инвентаризация и heartbeat | Агент передаёт поддерживаемые процессы/контейнеры, ресурсы и health; stale данные явно обозначаются |
| SEC-01 | Хранение доступа к узлам | Секреты шифруются; ключи вне БД; в API/логах нет plaintext; доступ ограничен владельцем |
| SEC-02 | Защита передачи секретов | HTTPS обязательно; серверные секреты дополнительно передаются в стандартном зашифрованном envelope, см. security |
| OBS-01 | Нагрузка | CPU, RAM, disk/inodes, I/O и network с единицами, timestamp, окном и признаком пропуска |
| OBS-02 | Пользователи | Отдельно registered/active платформы и показатели сервисов при наличии интеграции; неизвестное не равно нулю |
| GRAF-01 | Grafana для каждого сервиса | Привязанный dashboard UID и tenant-scoped доступ; чужие метрики недоступны |
| MOVE-01 | Перенос сервиса | План, совместимость, зависимости, backup, preflight, подтверждение, прогресс, healthcheck, cutover и recovery |
| CAP-01 | Оценка ресурсов | Предупреждение содержит метрику, окно, порог, причину и рекомендацию; недостаточные данные дают unknown |

«Перенести функционал» трактуется как перенос поддерживаемого развёртывания,
конфигурации, данных и зависимостей между узлами. Произвольное извлечение части
кода из одного приложения в другое требует отдельного проекта интеграции.

«Backend знает всё» означает модель обнаруженных ресурсов с timestamp,
источником и confidence. Первые adapters: Linux/systemd и Docker/Compose.
Необнаруженное и недоступное отображается как unknown, а не как healthy.

Открытые вопросы: число узлов/пользователей, retention, SLO/RPO/RTO, целевые
Linux-дистрибутивы, первый переносимый сервис, допустимый простой и размещение
Grafana. Эти параметры уточняются перед соответствующим этапом.
