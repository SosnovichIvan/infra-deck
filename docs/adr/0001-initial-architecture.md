# ADR 0001: стартовая архитектура

Дата: 2026-10-26. Статус: proposed, требует выбора перед реализацией runtime.

Контекст: небольшой новый проект с UI, доступами к серверам, background jobs,
наблюдаемостью и переносами. Измерений нагрузки и эксплуатационного бюджета нет.

Варианты:

- React/TypeScript + Python/FastAPI + Python agent: общий язык API/агента,
  быстрая разработка orchestration; агенту нужен упакованный runtime.
- React/TypeScript + Go backend/agent: автономные binaries и простой rollout;
  другой язык и отдельное решение для branch coverage по текущим правилам.
- Распределённые backend-микросервисы: независимое масштабирование, но больше
  сетевых отказов и расходов на эксплуатацию без текущего обоснования.

Предложение: React/TypeScript с FSD; Python/FastAPI API и worker; Python agent
с минимальными зависимостями; PostgreSQL; Prometheus-compatible telemetry и
Grafana. Очередь PostgreSQL для начала, отдельный брокер — после измерений.
Версии и lockfiles фиксируются в первом PR компонента.

Последствия: одна codebase backend облегчает транзакции и тестирование;
worker и API масштабируются отдельно. Обновление Python agent должно быть
атомарным с подписанным артефактом и возможностью возврата версии.
Возможен переход на Go agent без смены версионированного протокола.

Проверка: изоляция tenant, повтор jobs после crash, восстановление agent,
задержка telemetry, resource footprint на целевых VM и стоимость эксплуатации.
Численные бюджеты и SLO задаются после уточнения масштаба; обещаний capacity нет.
Пересмотр: measured очередь/latency или footprint не укладывается в эти бюджеты.
